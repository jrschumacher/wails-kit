## 0.1.0 (2026-08-05)

Initial release. Everything below is new; there is no prior version to diff
against.

### Features

* **settings:** schema-driven settings framework. The Go backend declares
  fields, types, options, defaults, validation rules and visibility conditions
  as a `Schema`; any frontend renders a settings page from it dynamically rather
  than hard-coding a form. Adding a setting means editing a Go struct literal,
  not a form component, a TypeScript type and a validation schema to match.
* **settings:** `Service.Bindings()` — a narrow, frontend-facing struct exposing
  exactly `GetSchema`, `GetValues`, `SetValues` and `Corruption`. Wails binds
  every exported method of a bound value, so binding a `Service` directly would
  publish `GetSecret` and `GetValuesWithSecrets` to the webview; `Bindings` is
  what makes the secrets model hold.
* **settings:** persistent JSON store in the platform user config directory —
  `~/Library/Application Support/<app>/settings.json` on macOS,
  `%AppData%\<app>\settings.json` on Windows, `~/.config/<app>/settings.json` on
  Linux. The directory is created `0700` and the file `0600`, and writes go
  through a temp file, an fsync and an atomic rename, so a crash mid-write
  cannot truncate the user's settings. `WithStorePath` overrides the location.
* **settings:** corrupt-config quarantine. A settings file containing invalid
  JSON is renamed to `<path>.corrupt-<timestamp>`, the service continues on
  schema defaults, and the app stays usable and saveable instead of failing
  every subsequent save. Because that recovery discards preferences it is
  reported rather than logged: `Service.Corruption()` returns a `CorruptConfig`
  so the app can tell the user what happened and where their old file went. Only
  malformed JSON is quarantined — an unreadable file still surfaces as an error.
* **settings:** two-tier validation. `ValidateSchema` checks the schema the
  developer wrote and returns a single joined `error` — unknown or missing field
  types, selects with no options, select defaults not among their own options,
  duplicate keys, conditions and `DynamicOptions` referencing undeclared fields,
  self-referencing conditions, uncompilable patterns, unsatisfiable
  `MinLen`/`MaxLen` and `Min`/`Max` ranges, password fields with a `Default`, and
  compute keys not declared as fields. `Validate` checks the values the user
  entered and returns one `ValidationError` per problem, addressed by field key.
  `NewService` runs `ValidateSchema` at construction, so a structurally broken
  schema fails at startup rather than reaching an end user as a control that
  never appears.
* **settings:** `Condition.Equals` is `[]any`, so a field can be gated on a
  toggle or a number, not only on a select. Numbers compare numerically across
  every Go numeric type, so a schema behaves identically whether the value came
  from Go or across the JSON bridge; comparison never crosses kinds, so `"true"`
  never matches `true`.
* **settings:** `SetValues` validates against the effective post-save state —
  defaults, then the config file, then the submission, with secrets resolved and
  compute functions applied — so a frontend posting one group at a time is
  judged correctly rather than failing on untouched required fields. Undeclared
  keys are rejected rather than silently dropped, and nothing is written unless
  validation passes completely.
* **settings:** `SecretStore` abstraction for `FieldPassword` values, which are
  never written to `settings.json`. Defaults to the OS credential store —
  Keychain on macOS, Credential Manager on Windows, Secret Service over D-Bus on
  Linux — and fails loudly rather than falling back to plaintext on disk.
  `WithPlaintextFileSecrets` is an explicit, opt-in escape hatch for headless
  environments, and `WithSecretStore` allows injecting a store in tests.
* **settings:** `SecretSentinel` round-trip. `GetValues` reports a stored secret
  as the sentinel and omits one that was never set, so no real API key crosses
  the Wails bridge; `SetValues` reads the sentinel as "leave the stored secret
  alone", an empty string as "clear it", and anything else as a replacement.
  `GetValuesWithSecrets` and `GetSecret` resolve real values and are Go-only by
  construction. `onChange` listeners receive the masked map.
* **llm:** provider-neutral streaming chat abstraction. `Provider`,
  `ChatRequest`, `ChatMessage`, tool definitions, tool calls and tool results are
  modelled in this package rather than borrowed from a vendor SDK, so
  application code compiles against `llm` alone and switching providers is a
  settings change. `Role`, `EventType` and `StopReason` are named types over
  `string`, so untyped literals stay assignable.
* **llm:** streaming event contract. Every stream ends with exactly one terminal
  event — `EventDone` carrying the `StopReason` the model actually stopped for,
  emitted for every terminal condition rather than only a natural end of turn, or
  `EventError` carrying the same error `StreamChat` returns. `EventToolUse` is
  emitted only once fragmented tool-call arguments have been reassembled, so
  `ToolUseBlock.Input` is never a partial document.
* **llm:** provider registration by blank import. The `llm` package contains no
  provider implementations and imports no vendor SDK; provider packages register
  themselves from `init` via `RegisterProvider`. The set of providers a binary
  can build is exactly the set of provider packages it imports, so an app that
  only ships Anthropic support never links the OpenAI SDK.
  `RegisteredProviders()` reports what the running binary can actually build.
* **llm:** third-party provider extensibility. A provider outside this module is
  a peer of the built-in ones: `RegisterProvider` plus `WithTransportResolver`
  lets it send traffic over another registered provider's wire protocol with no
  changes to the factory, and `LLMSettingsGroup(WithProvider(...))` gives it its
  own fields and model list in the settings UI.
* **llm:** `LLMSettingsGroup` takes options — `WithProviders` to restrict and
  reorder the provider select, `WithProvider` to add or replace one,
  `WithModels` and `WithExtraModels` to correct the built-in model lists, which
  are a snapshot and go stale as soon as a vendor ships a new model. Called with
  no options it describes the built-in providers. Provider and model defaults
  follow the resulting list rather than being pinned, so restricting providers
  cannot leave `llm.provider` defaulting to one that is no longer offered.
* **llm:** `ProviderManager` builds a `Provider` from a `settings.Service` on
  demand, caches it, and rebuilds it on `Reload`. It resolves real secrets
  internally via `GetValuesWithSecrets` and never hands them out, so application
  code holds a working provider without ever holding the key. On a failed reload
  the cached provider is dropped rather than kept, so requests cannot silently
  keep going to the previous configuration.
* **llm:** `NewProviderFromValues` rejects a values map whose API key is
  `settings.SecretSentinel`. Passing `GetValues` output instead of
  `GetValuesWithSecrets` compiles cleanly and would otherwise surface only as an
  opaque 401 from someone else's API, far from the mistake.
* **llm/anthropic:** Anthropic provider with streaming, tool use and Cloudflare
  AI Gateway support. Registers a `TransportResolver` so selecting the
  OpenAI-compatible API format routes Anthropic models through the OpenAI
  transport under an `anthropic/` model prefix — knowledge that lives in the
  provider package, not in the factory.
* **llm/openai:** OpenAI provider with streaming, tool use and Cloudflare AI
  Gateway support.
* **llm/mock:** provider for testing downstream applications without a network
  or the OS keyring. Usable as a hand-configured stub, and self-registering via
  blank import so the whole settings-to-provider path can be exercised end to
  end.
